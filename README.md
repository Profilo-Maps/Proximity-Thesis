# Proximity Model — Active Transport Infrastructure Graph

Processes OpenStreetMap and government datasets to generate per-city street network parquet files with detailed sidewalk, bikeway, crosswalk, and curb ramp attributes. Implements the 21-step pipeline defined in [`specs/ProximityNetworkDescription.md`](../../../specs/ProximityNetworkDescription.md).

---

## Files

| File | Role |
|---|---|
| `ProximityModel.py` | Main pipeline (21 steps) |
| `ProximityModelUI.py` | Configuration GUI |
| `verify_parquet.py` | Output validation and diagnostic maps |
| `run_pipeline.bat` | Windows convenience launcher |
| `config.json` | Saved city and global configuration |

### Data
- `Data/` — Government source files (parcels, curb ramps, etc.)
- `Output/` — Generated parquet files and diagnostic maps
- `cache/` — OSMnx tile cache

## Quick Start

### Windows (recommended)
Double-click `run_pipeline.bat` and select from the menu:
1. **Launch Configuration UI** — First-time setup or changing settings
2. **Run Analysis + Verification** — For pre-configured setups
3. **Run Verification Only** — To validate existing output files

### Manual
```bash
# Step 1: Configure (first time only)
python ProximityModelUI.py

# Step 2: Run pipeline
python ProximityModel.py

# Step 3: Verify output
python verify_parquet.py
```

## Configuration

### Global Settings
| Setting | Description |
|---|---|
| Output Directory | Where parquet files are saved |
| Default Max Speed | Default speed limit (mph) |
| Curb Ramp Buffers | Inner/outer trustworthiness buffers (meters) |
| GPU Usage | Enable/disable GPU acceleration |
| Python Environment | Path to Python executable |

### Per-City Settings
Each city entry configures:
- **Name** — Used for OSM query (e.g., `"San Francisco County, CA"`)
- **Government Data Paths** — Parcels, street centerlines, intersection nodes, sidewalks, bikelanes, curb ramps, crosswalks, street/sidewalk/bikeway features
- **Column Mappings** — Maps government data columns to the output schema
- **Curb Ramp Trustworthy** — Whether to trust government curb ramp geometry

## Output Files

For each city the pipeline produces:

### `{CityName}_network.parquet` — 206 columns
| Category | Columns | Count |
|---|---|---|
| Block & Street | IDs, attributes, features | 18 |
| Sidewalks | 2 sides × (8 base + 36 curb ramps + 5 features) | 88 |
| Crosswalks | 2 slots × 15 attributes each | 30 |
| Bikeways | 2 sides × 2 lanes × (8 base + 5 features + buffered flag) | 60 |
| Geometries | WKB bytes (all CRS EPSG:4326) | 10 |

All geometry columns store WKB bytes in EPSG:4326. The pipeline works internally in a local projected metric CRS and converts back at export.

### `{CityName}_sanity.parquet`
Sanity buffer map: `osmid`, `max_offset_width` (meters).

### `Output/Diagnostic Maps/`
Visual PNG maps generated by `verify_parquet.py`:
- Street network coverage
- Sidewalk / bikeway presence
- Curb ramp locations
- Crosswalk locations
- Block structure and assignment

## Schema Reference

### Key Column Patterns

**Sidewalk** (side = `left` / `right`):
- `sidewalk_{side}_feature_ids`, `sidewalk_{side}_feature_types`
- `public_data_id_sidewalk_{side}_feature`
- `sidewalk_{side}_feature_geometry`, `sidewalk_{side}_feature_geometry_projected`
- `public_data_id_sidewalk_{side}_curbramp_{slot}_{pos}`
- `sidewalk_{side}_curbramp_{slot}_{pos}_returnposition`

**Bikeway** (side = `left` / `right`, n = `1` / `2`):
- `bikeway_{side}_{n}_id`, `bikeway_{side}_{n}_block_id`
- `bikeway_{side}_{n}_type`, `bikeway_{side}_{n}_surface`, `bikeway_{side}_{n}_permitted`
- `bikeway_{side}_{n}_width`, `bikeway_{side}_{n}_incline`
- `public_data_id_bikeway_{side}_{n}`, `public_data_id_bikeway_{side}_{n}_features`
- `bikeway_{side}_{n}_feature_ids`, `bikeway_{side}_{n}_feature_types`
- `bikeway_{side}_{n}_feature_geometry`, `bikeway_{side}_{n}_feature_geometry_projected`

**Crosswalk** (slot = `start` / `end`):
- `public_data_id_crosswalk_{slot}`
- `crosswalk_{slot}_controlled`, `crosswalk_{slot}_marked`, `crosswalk_{slot}_markings`
- `crosswalk_{slot}_signals` — `[signals_present, button, sound, vibration, flashing]`

**Geometry**:
- `start_node_geometry`, `end_node_geometry`
- `bikeway_left_2_geometry`, `bikeway_right_2_geometry`

**Bearing**:
- `bearing` — Full 360° bearing
- `normalized_bearing` — Mapped to [0, 180)

## Verification (`verify_parquet.py`)

Checks performed:
- All 206+ expected columns present
- Valid WKB geometries for all geometry columns
- Sequential IDs are positive integers (`bikeway_left_2_id`, `bikeway_right_2_id`, `crosswalk_end_id`, etc.)
- Curb ramp trustworthiness: when `curbramp_trustworthy=False`, no government ramp IDs are populated
- Default (model-generated) curb ramp presence
- Curb return geometries valid
- MultiPoint feature geometries valid (original and projected)
- Block ID tuples, block side labels, block node flags

## Known Issues & Fixes

### OSMNetwork.py Import (resolved Feb 22 2026)
`load_curb_ramps`, `assign_curb_ramps`, and `extract_curb_return_geometries` are imported from `OSMNetwork.py` via a try/except block with `OSM_NETWORK_AVAILABLE` flag and wrapper functions bridging signature differences. If `OSMNetwork.py` is absent, the pipeline degrades gracefully.

### `bikeway_left_2_block_id` naming
Both `bikeway_left_1_block_id` and `bikeway_left_2_block_id` are distinct columns tracking two bikeways on the same side. This is intentional.

### `crosswalk_start_signals` format
Stored as `[signals_present, button, sound, vibration, flashing]`. Equivalent to the spec's `List[yes/no, ...]` format.

## Performance

| City size | Approximate runtime |
|---|---|
| < 10k streets | 5–15 min |
| 10k–50k streets | 15–60 min |
| > 50k streets | 1–3 hours |

GPU acceleration (CuPy or PyTorch CUDA) speeds up nearest-neighbor searches, spatial distance calculations, and parcel distance computations. Disable if screen flickering occurs (`use_gpu = False`).

## Troubleshooting

| Problem | Fix |
|---|---|
| GPU screen flickering | Set `use_gpu = False` in Global Settings |
| Conda env not found | Run `conda env list`, ensure `ParkximityENV` exists |
| OSM fetch fails | Check internet and exact city name spelling |
| Column mapping errors | Use "Column Config" in UI; do not map geometry columns manually |
| Parquet validation fails | Check console output; verify input files exist and are EPSG:4326 |
